### **Coordinate System and Constraints**  

- **World Frame Orientation:** 
  - **X-axis:** Front of the table, or away from the robot base (positive); back of the table, or close to the robot base (negative).
  - **Y-axis:** Left (positive), Right (negative). Left and right are defined as seen from the robot base.
  - **Z-axis:** Up (positive, towards the ceiling), Down (negative, towards the floor)  
  - **Origin:** [0, 0, 0] is at the base of the robot arm.  
  - **Pose definition:** All given poses use the format {'position': [p_x, p_y, p_z], 'orientation': [Roll, Pitch, Yaw]}. 'position' holds the x, y, z coordinates and 'orientation' holds Euler angles in the XYZ convention. Note that the position in 'robot_state' is the position of the center of the gripper fingers.
  - **Robot state:** An orientation of [np.pi, 0, 0] or [-np.pi, 0, 0] is the neutral orientation: the gripper points downwards and its two fingers are aligned along the Y-axis, allowing it to grasp objects from the XZ plane. An orientation of [0, np.pi/2, 0] points the gripper horizontally along +X, away from the robot base, with its fingers again aligned along the Y-axis; [np.pi, np.pi/2, 0] instead points the gripper back toward the robot base. With a pitch of np.pi/2, roll and yaw both only turn the gripper's horizontal heading (heading angle = yaw - roll), so keep roll at 0 and yaw at 0 to approach along +X.

- **Robot Physical Constraints and Table Workspace:**  
  1. The gripper has two parallel fingers (0.025m each) that can open up to 0.085m.

```python
class RealFrankaRobotApi:
    """Interface for interacting with the Franka Panda robot."""

    def close_gripper(self):
        """Closes the gripper."""

    def locate_object_part(self, object_name, part_description):
        """
        Given an object name and a part description (e.g., "the front tip of the hammer"),
        estimate the 3D position of the corresponding feature point.

        This function first samples several visible points from the object mask, maps them from camera space to world space, 
        and uses a vision-language model to select the most relevant point(s) based on the part description.

        Example input: 
            object_name: "blue box"
            part_description: "the center of the front surface of the box"
        
        Example output: 
            [
                {
                    '3d_position': [0.67, 0.21, 0.24],
                    'label': 'the center of the front surface of the box',
                    'index': 4
                },
                ...
            ]

        Notes:
        - The point selection is performed via a VLM (vision-language model), so ensure that the object is clearly visible in the image.
        - Avoid part descriptions referring to occluded or ambiguous features (e.g., "bottom center of the object"), unless visible proxies can be used.
        - The index field corresponds to the sampled point index (1-based) for traceability.
        - The feature points to be queried must all be visible and correspond to real points on the object, rather than floating geometric points. If you need such geometric points, you can query multiple physical points within this function and compute the desired position based on them.
        - This function uses the robot's wrist camera. When the robot is holding something in the gripper, the wrist camera is occluded and this function does not work correctly, so avoid calling it while the robot is already holding something.
        """

        
    def get_robot_state(self):
        """Return the environment state at the current time. The keys in the state are the same as in the initial state."""

    def move_to_pose(self, position, orientation):
        """Moves the gripper to a given position and orientation. The orientation is [Roll, Pitch, Yaw], the angles about the x, y and z axes."""
            
    def open_gripper(self):
        """Opens the gripper."""
    
    def locate_objects(self, labels):
        """
        Point to multiple objects using a vision-language pointing model.
        
        This is the most accurate and efficient pointing method, although it can still make mistakes and has weaknesses. It intelligently:
        - Searches through pre-scanned wrist camera poses to find the best view for each object
        - Can locate multiple objects simultaneously, even if they're in different locations
        - Returns precise 3D world coordinates for each object

        
        Args:
            labels: List of object names/descriptions to locate (e.g., ["red cup", "banana", "knife handle"])
        
        Returns:
            List of results for each found object:
            [
                {
                    'label': 'red cup',
                    '2d_position': (y_pixel, x_pixel),
                    '3d_position': [x_world, y_world, z_world]
                },
                {
                    'label': 'banana',
                    '2d_position': (y_pixel, x_pixel),
                    '3d_position': [x_world, y_world, z_world]
                },
                ...
            ]
        
        Example usage:
            # Locate multiple objects at once
            results = robot.locate_objects(['red cup', 'green bowl', 'yellow banana'])
            
            # Extract positions
            for item in results:
                print(f"{item['label']} is at {item['3d_position']}")
                # Visualize the detected point
                image_editor.draw_point(item['3d_position'])
            
            # Use for grasping
            red_cup_pos = next(r['3d_position'] for r in results if 'red cup' in r['label'])
            robot.move_to_pose(red_cup_pos, [np.pi, 0, 0])
        
        Notes:
        - The robot will automatically move its wrist camera to optimal viewing angles
        - Objects are automatically visualized with labels on the step images
        - Prefer this over other pointing methods. If it does not work, try locate_object_by_segmentation or locate_object_part, or rescan. Both of those use GroundedSAM, so if one of them fails, GroundedSAM cannot handle this object; rephrase the object name and use locate_objects again.
        - If objects are not found, this returns partial results. You can call refresh_scan() to refresh the cache.
        """

    def refresh_scan(self):
        """
        Invalidate the wrist scan cache and perform a fresh scan with new camera views.
        
        Use this when:
        - locate_objects() failed to find some objects, which may be because an object has been moved or the scene has changed, so the scan needs to be refreshed
        
        This function will:
        1. Discard the old cached wrist camera views
        2. Move the robot to capture 8 new views from different angles
        3. Save the new cache for subsequent locate_objects() calls
        
        Example usage:
            # Try to find objects
            results = robot.locate_objects(['red cup', 'blue bowl'])
            
            # If some objects are missing and you think they should be visible
            if len(results) < 2:
                print("Some objects not found, rescanning...")
                robot.refresh_scan()  # Fresh scan
                results = robot.locate_objects(['red cup', 'blue bowl'])  # Try again
        
        Notes:
        - Only use it when necessary (the scene changed or objects are missing)
        - After rescanning, call locate_objects() again to locate objects
        """

    def detect_bounding_box(self, object_name):
        """
        Quickly segment and return a bounding box for `object_name` in the current wrist view.
        Args:
            object_name: Text prompt for grounded segmentation (e.g., "red cup").
        Returns:
            {'box': [x1, y1, x2, y2], 'logit': float} or None if unavailable.
        """

    def locate_object_by_segmentation(self, object_name, z_offset=0.0):
        """
        Return a coarse 3D interaction point using the bounding-box center.
        
        - Uses grounded segmentation to get a box and projects its center to 3D.
        - Adds optional vertical offset in world Z.
        Args:
            object_name: The target object name or phrase.
            z_offset: Optional vertical offset in meters.
        Returns:
            {'box': [...], 'pixel': [y, x], '3d_position': [x, y, z], 'logit': float} or None.
        """


    def propose_grasps(self, object_name):
        """
        Propose grasp candidates for an object, or for the part of an object named in object_name.

        This function segments the object with GroundedSAM and moves the wrist camera around it to fuse
        a multi-view point cloud of the segmented region. GraspGen samples 6-DoF grasps on that point
        cloud and keeps the confident ones. Each grasp is then corrected to the pose convention of
        move_to_pose: a fixed rotation about the approach axis and an offset to the center of the fingers.

        Args:
            object_name: Name of the target object to grasp (e.g., "the green cup", "handle of the water bottle").
        Returns:
            result: A list of tuples, where each tuple contains:
                - position: np.ndarray of shape (3,), the 3D grasp position.
                - orientation: np.ndarray of shape (3,), [Roll, Pitch, Yaw].
        """

    def execute_grasp(self, grasps):
        """
        Plan and execute a grasp motion for the robot to pick up an object using a given set of grasp candidates.

        This function first obtains the current joint positions and computes the goal poses for the given grasp 
        candidates. It then plans a motion to execute the grasp, moves the robot along the planned trajectory to the grasp pose and closes the gripper to grasp the object.
        Args:
            grasps: A list of grasp candidates, where each element is a tuple of 
                    (position: np.ndarray of shape (3,), orientation: np.ndarray of shape (3,), [Roll, Pitch, Yaw]).

        Returns:
            None. The function executes the grasp motion and closes the gripper directly on the robot.
        """
    def measure_distance(self, position1, position2):
        """Measures the Euclidean distance between two 3D positions."""
    
    def measure_vector(self, position1, position2):
        """Measures the vector from position1 to position2."""
    
    def euler_to_rotation_matrix(self, euler):
        """Converts Roll, Pitch, Yaw to rotation matrix."""
    
    def rotation_matrix_to_euler(self, rotation_matrix):
        """Converts rotation matrix to Roll, Pitch, Yaw."""

    def measure_relative_rotation(self, vector1, vector2):
        """
        Measures the rotation (Roll, Pitch, Yaw) to rotate vector1 to vector2.
        A common use of this function is to provide the current position and target position of a vector, and it will output the rotation needed to reach the target.
        """

    def rotate_by(self, current_orientation, rotation):
        """Rotates the given orientation (Roll, Pitch, Yaw) by the given rotation (Roll, Pitch, Yaw)."""

    def reset(self):
        """Resets the robot to its initial state."""


    
```

### Pointing and Grasp Strategy

- **Pointing (choose based on interaction needs):**
  - **First choice, locate_objects (fast & versatile):** Use this as your primary pointing method. It uses VLM pointing, which can accurately locate either an object or a specific part of an object. It can find multiple objects at once, even if they're in different locations. The robot automatically finds the best camera angle for each object.
    - Use for: Almost all object localization tasks (grasping, pushing, pressing, pick-and-place) and pointing to specific parts
    - Fast and efficient
    - Example: `results = robot.locate_objects(['red cup', 'banana', 'rim of the cup', 'handle of the knife'])`
  
  - **Second choice, locate_object_by_segmentation (fast for whole objects):** Use `locate_object_by_segmentation` as your second choice when you need to point to whole objects. It's fast: it segments the object with GroundedSAM and points at the center of the bounding box.
    - Use for: Whole object localization when locate_objects doesn't work
    - Not suitable for pointing to specific parts of an object
  
  - **Last resort, locate_object_part (slow but accurate):** Use `locate_object_part` as your last resort, only when both locate_objects and locate_object_by_segmentation fail, or when you need to point to very specific functional parts of an object (e.g., "front-left corner of towel", "specific button on keyboard"). locate_object_part is best at such parts, sometimes even better than locate_objects.
    - Use for: Precise part-level localization when the other methods don't work
    - Slow but can be very accurate for functional parts
    - Should be avoided if possible due to speed

- **Grasp selection:**
  - **Simple objects (regular shapes, or deformable objects like a towel) or top-down grasps:** Use `locate_objects` to locate the object, then design a manual top-down grasp.
    - Example: Get position -> move above -> approach -> close gripper
  - **Complex/articulated objects or side grasps with specific orientation constraints:** Use `locate_objects` for locating and `propose_grasps` + `execute_grasp` to grasp. When a top-down grasp may not be feasible (it may cause a collision) and you need to grasp something from the side, you should consider using propose_grasps instead of a manually designed grasp.
  - **Functional part grasps:** Use `locate_objects` for the specific part first, then `locate_object_part` as backup if needed, then manual grasp design.
    If the target object is not on the table and a top-down grasp may not be easy, you should prioritize propose_grasps over a manual top-down grasp.
- **Non-grasp tasks (pushing/pressing/approach):**
  - Use the same pointing order as above: `locate_objects` (which also works for specific parts of an object), then `locate_object_by_segmentation`, then `locate_object_part` as a last resort.

- **Suggested workflows:**
  - Simple tabletop top-down pick-and-place: **locate_objects -> visualize with draw_point -> manual top-down grasp** (or locate_object_by_segmentation as fallback)
  - Multiple objects: **locate_objects (batch) -> process each result -> grasp**
  - Functional part grasp: **locate_objects -> manual grasp**, use locate_object_part as last resort
  - Articulated objects or grasp from a certain orientation (from the side for example): **locate_objects -> propose_grasps -> execute_grasp**

Hints:
    a. If the robot state does not change after you call `robot.move_to_pose`, that is because the target position is not reachable and the motion planner stopped the motion. Due to limitations of the controller, a sudden large change in angle may cause the target to be unreachable. If this happens, you can add some intermediate steps.
    b. If you fail at a step, it is very likely that your plan and code are wrong. Carefully check whether you misunderstood the observation. You should not just retry your wrong plan over and over.
    c. Local variables are shared among different steps. You can directly use the variables defined in previous steps and do not need to set anything in global scope. For multi-step tasks (e.g., sequentially picking and placing multiple objects), always detect all objects once at the very beginning using locate_objects, store the results in a dictionary (e.g., `object_positions = {item['label']: np.array(item['3d_position']) for item in results}`), and then reuse this dictionary in all subsequent steps. Never call locate_objects repeatedly for the same objects: each redundant call wastes significant time (~25-35 seconds) and API costs. Objects on the table typically don't move between your pick-and-place operations, so their positions remain valid throughout the task.
    d. Your code will be parsed and executed by the system without any modification. Please do not comment out the useful parts of the code.
    e. The motion planning of the robot arm is not collision-free. Therefore, when you want to move the gripper to a certain position, it's best to manually define enough safe waypoints to avoid collisions. For example, you can first lift to a safe height before moving horizontally to avoid hitting other objects on the table.
    f. When you need to perform a grasp operation, you should first try using `propose_grasps` and `execute_grasp`. Consider trying other approaches only if they fail. Note that these functions can be rewarding but aggressive, and they sometimes generate accurate but unusual and kinematically infeasible grasp poses. So right before using these functions, make a good estimate of the grasp pose yourself (for example as grasp_in_mind) using the existing tools and the object pose information, and compare it with the candidates returned by propose_grasps before calling execute_grasp. If they differ too much, execute your manually estimated grasp pose instead to avoid getting stuck.
    g. When you need to move an already-grasped object to a target position or orientation, always follow the approach shown in the example code below and use API functions such as `measure_relative_rotation`, `rotate_by`, `measure_vector`, `measure_distance`, rather than directly estimating a target pose in a naive way. Use these vector functions together with the feature points you obtained from locate_object_part to get more accurate estimates.
    h. If you want to reason about precise orientation, always try to use the spatial reasoning functions measure_relative_rotation, rotate_by and measure_vector.
